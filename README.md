# SK하이닉스 AI 해커톤 2026 — 2차 예선 본시험용 하네스

응시자가 AI와 작업하는 순서와 문서 양식을 정리한 개인 준비용 공개 저장소입니다. SK하이닉스·크래프톤·OpenAI의 공식 배포물 또는 승인 자료가 아니며, 실제 시험 문제·자료·정답은 포함하지 않습니다. 하이닉스 1차 예선 자료는 참고하지 않았습니다.

## 핵심 흐름

**짧은 구현 전 계획 → 기능별 구현·검증·설명 초안 → 사용자 직접 기능 테스트 → 수정·재검증 → 최종 구현 문서·이해 확인 → 제출 점검**

1. 실제 과제 README와 기존 지침을 읽고 필수 제출물·파일명·제출 위치를 확인합니다.
2. 구현 코드를 작성하기 전에 짧은 계획과 필수 문서 뼈대를 만듭니다. 목표·요구사항·구현 방식·작업 순서·검증·시간 배분을 적습니다.
3. 합의된 범위의 핵심 기능부터 구현하고 AI가 수행 가능한 검증을 직접 실행합니다. 요구사항별 실제 산출물·코드·검증 근거를 연결하고, 기능이 동작할 때마다 처리 흐름·선택 이유·실패 조건을 짧게 설명합니다.
4. 사용자에게 기능별 테스트 순서와 기대 결과를 안내합니다. 사용자 확인을 기다리는 동안 미확인 기능을 통과로 표시하지 않습니다.
5. 사용자가 테스트 결과를 알려주면 실패·보완 사항을 수정하고 관련 검증을 다시 수행합니다. 수정이 사용자 확인에 영향을 주면 해당 부분의 재확인을 요청합니다.
6. 사용자가 해당 판본·범위의 기능 테스트 완료를 알린 뒤, 구현 중 축적한 설명을 최신 코드·검증 근거와 대조해 상세 문서로 확정합니다. 미완료·미실시 범위는 명시하고 제출을 무기한 막지 않습니다.
7. 상세 문서를 읽고 구조·판단 이유·실패 조건을 이해한 뒤 플랫폼에서 제출합니다. 후속 서술형 등 AI 금지 단계에서는 답변·첨삭·설명을 요청하지 않습니다.

## 시험 환경에서 사용

최신 운영 안내가 허용한 제공 작업 공간의 터미널에서 가져옵니다.

```sh
pwd
ls -a
git clone https://github.com/CLM-BONNY/cofa-exam-harness.git
codex
```

실제 과제 폴더에서 Codex를 실행하고 [START.md](START.md)의 시작 요청을 전달하세요. clone 위치가 다르면 경로를 바꿉니다. 하위 폴더의 [AGENTS.md](AGENTS.md)가 과제 전체에 자동 적용된다고 가정하지 않고 명시적으로 읽게 합니다. 기존 지침을 복사본으로 덮어쓰지 않습니다.

이후에는 [PROMPTS.md](PROMPTS.md)에서 현재 단계에 필요한 요청만 선택하거나 해당 절을 읽도록 요청합니다. 작업 환경 내 복사·붙여넣기는 실제 과제의 허용 범위를 따릅니다. 후속 서술형 등 AI 금지 단계에서는 사용하지 않습니다.

필요 문서는 과제가 허용한 실제 작업 위치에 새로 작성합니다. 하네스 폴더 안에 결과물을 작성하거나 여기에 Git Push하지 않습니다. 별도 설치·자동 초기화·전역 설정 변경·실행 스크립트·외부 의존성은 없습니다.

## 시간 운영과 복구

실제 타이머·과제 안내가 우선입니다. 아래는 작업 180분일 때의 조정 가능한 권장 예산입니다.

| 구간 | 작업 | 분 |
| --- | --- | --- |
| 시작~20분 | 본인 확인·환경·과제 확인과 짧은 계획 | 20 |
| 20~60분 | 핵심 입력→처리→출력이 실행되는 첫 버전 | 40 |
| 60~105분 | 필수 기능 확장·기능별 검증 | 45 |
| 105~130분 | 오류·경계값·동일 실패 사례 재검증 | 25 |
| 130~150분 | 사용자 기능 테스트·수정 | 20 |
| 150~170분 | 최종 문서·본인 이해 확인 | 20 |
| 170~180분 | 제출 미리보기·저장 확인·과제 제출 확정 | 10 |

60분 안에 핵심 흐름이 실행되지 않으면 선택 기능과 불필요한 추상화를 중단합니다. 마지막 30분에는 필수 결함 수정·문서 일치·제출을 우선합니다. 질문 준비 대기·후속 답변·업로드 시간도 전체 종료 시각 안에 남겨야 합니다. 실제 문항 수와 제한 시간은 최신 안내·응시 화면에서 확인합니다.

중요한 단계마다 WORKLOG 상단에 실행 방법·완료 범위·마지막 검증·미해결 문제·다음 작업을 갱신합니다. 연결 복구 뒤에는 저장 파일과 프로세스를 확인해 이어갑니다. 불필요한 서버·감시 프로세스를 쌓지 않고, 승인 대기를 실행 실패로 오인해 요청을 중복 발행하지 않습니다.

## 역할과 사실 구분

- AI가 직접 수행 가능한 코드·명령 검증은 AI가 합니다. 사용자 테스트로 대신하지 않습니다.
- 화면과 실제 업무 흐름은 사용자가 직접 테스트하고, 본인이 알려준 범위·판본의 결과만 기록합니다.
- AI 검증 통과, 사용자 테스트 완료, 제출 완료는 서로 다른 상태입니다.
- 문서 제공은 사용자 이해 완료의 증거가 아닙니다.
- 이 저장소는 작업 지침입니다. 검증·감독·제출을 자동 보장하는 프로그램이 아닙니다.

## 규정과 자료

최신 공식 안내·실제 과제 지침을 우선합니다. 제공된 Codex와 허용 모델만 사용하고 도구 버전·관리·감독 설정을 변경하지 않습니다. Computer Use 등 금지된 자동 조작을 사용하지 않습니다. 문제·파일·코드·결과·로그·개인정보를 외부로 전송하거나 Git Push하지 않습니다. 공개 자료는 과제가 허용한 경로로 반입하고, 사용한 저장소는 2차 예선 결과 통지 전까지 공개 상태를 유지합니다. 변경된 운영 안내가 있으면 그 안내를 우선합니다. 사전 체험 환경·파일·설정이 본시험에 유지된다고 가정하지 않습니다.

본시험 사용 전 공개 저장소 내용과 적용 범위를 확인하세요. 이 키트의 실제 시험 환경 동작과 점수 향상은 검증하지 않았습니다.
